# WarioWare 式 microgame 合集 核心机制与算法

## 1. 宿主状态机
```
BOOT → 显示指令(prompt, 0.8s) → 进行中(playing, 限时 T) → 结算(result)
result:
   win → 连胜+1, 进入下一关（T 缩短）
   lose → 生命-1, 重来本关 或 GameOver
生命=0 → GAMEOVER（展示最高连胜）
```
时间 `T(n)` 随关数递减：`T = max(Tmin, T0 - n*step)`（如 5s→1s）。

## 2. Microgame 契约（关键解耦）
宿主只调用统一接口，不关心具体玩法：
```
interface Microgame {
  id: string
  prompt: string                 // “躲开石头！”
  init(ctx): void                // ctx 提供 win()/lose()/canvas/input
  update(dt): void
  render(ctx): void
  onInput(ev): void              // ev: {type:'tap'|'drag'|'key'|'mash', ...}
}
```
- 小游戏在条件达成时调用 `ctx.win()`，失败/超时调用 `ctx.lose()`。
- 超时未 win 视为 lose。

## 3. 调度与抽取
```
games = [dodge, tap, count, mash, drag, ...]
next(): 随机或轮换取一个（避免连续重复）
```
可加权重/按难度分桶。

## 4. 输入抽象
统一事件类型，兼容键鼠与触屏：
- `tap`：点击/触摸（坐标）。
- `drag`：拖拽（起止点）。
- `key`：按键（code）。
- `mash`：单位时间按键/点击次数（狂按）。
宿主把原始事件翻译成上述类型传给当前 microgame。

## 5. 计时与渲染
- 倒计时用圆环/数字，最后 1 秒变红闪烁（紧张感）。
- 指令用超大字号居中，0.8s 后切到玩法画面。
- 过场：白屏闪 + 音效「咻」。

## 6. 计分
- 连胜 `combo` 为主分数；可 `score += base * comboMultiplier`。
- 最高连胜存 `localStorage`。

## 7. 新增小游戏流程（扩展）
1. 在 `microgames/` 新建文件，导出一个符合契约的对象。
2. 在 `loader` 注册。
3. 不改动宿主即可被随机抽取——这是架构价值所在。
