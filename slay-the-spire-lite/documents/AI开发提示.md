# 杀戮尖塔简化版 — AI 开发提示词

## 角色
你是熟悉回合制卡牌构筑（deckbuilder）的游戏工程师，能把复杂战斗拆成清晰的数据驱动系统。

## 目标
实现「杀戮尖塔」简化版：回合制战斗（抽牌/出牌耗能/敌人意图）、可叠加状态效果、节点地图推进、战后选卡与回血。纯前端，无后端、无账号。

## 开发流程
1. 卡牌数据模型 + DOM 渲染（费用、名称、描述、拖拽/点选出牌）。
2. 牌库循环：Fisher–Yates 洗牌、抽 5、出牌耗能、弃牌、回合结束洗回。
3. 战斗主循环：玩家出牌结算 → 敌人按展示的意图行动 → 状态结算。
4. 状态系统：中毒/易伤/虚弱等 `Map<status,stacks>`，回合结束统一结算。
5. 伤害公式：`base × weak × vulnerable`，先扣 block 再扣 hp。
6. 胜负与单场战斗闭环（先做到能打赢一场）。
7. 节点地图生成与推进、战斗间奖励（选卡/回血/遗物）。
8. 遗物被动、精英/Boss、移动端点选适配。

## 范围与限制
- 纯前端，无联网、无账号、无云存档（本地可存 run 进度）。
- **卡牌/敌人/遗物必须数据驱动**，新增内容只加数据，不改动主循环。
- 状态效果用统一的 `Map` 结构，禁止把每种状态写死成独立字段散落各处。
- 先做「单层 + 线性若干节点」可玩闭环，肉鸽深层地图作为扩展。
- 卡牌 20~40 张、敌人 5~8 种即足够验证。

## 禁忌
- 不要把卡牌效果写成大量 if/else 硬编码（用 effect 函数 + 配置）。
- 不要忽略「抽牌堆空时洗回弃牌堆」导致卡死。
- 不要忘记每回合清空/结算 block 与状态计时。
- 不要让敌人意图与实际行动不一致（玩家依赖意图决策）。

## 验收标准
- [ ] 抽牌、出牌耗能、弃牌、洗牌循环正确。
- [ ] 敌人意图正确显示并按之行动。
- [ ] 状态效果（中毒/易伤/虚弱）结算正确。
- [ ] 伤害公式与 block 抵消正确。
- [ ] 可打赢一场战斗，胜利后进入奖励/地图推进。
- [ ] 移动端点选出牌可用，界面不乱。
